Thompson

A small mechanism for changing things with agents. Every change is a card, every card carries a check, a judge the worker cannot edit decides whether the change counts, and the card folder keeps the whole story of how it got there.

Thompson has no model calls of its own. A host takes a card, runs attempts, and hands the result to the judge. A person merges.

score 0.000 · 0 agents

The recommended first problem, Flow, drawn live after 02_M's noise agents. Agents ride the field and stop when they crowd another trail; the score is the share of the page within half a spacing of a trail. Same field, same check, two seeding rules: the second is the kind of change a Thompson run should find on its own.

The five rules

  1. Nothing counts until the judge says so.
  2. The judged cannot edit the judge, the log, or a card's check.
  3. Every change is a card, every card has a check, every outcome is logged, including changes to the mechanism itself.
  4. Keep what raises the score, revert what lowers it.
  5. A failure writes the next card. A human ratifies each new check.

How a card runs

The refine host in adapters/refine runs a card like this, in order:

1 · card

Name the task

A title, what done means, and a check command that exits 0 or 1.

2 · rollouts

Two attempts

Each attempt generates a change, a critic reads it blind to the tests, and the worker corrects.

3 · judge

Run the check

The check and the project gates run on the attempt's commit in a throwaway worktree.

4 · keep

Pick the best pass

Highest score first, then lowest cost. A failure writes the next card.

5 · person

Merge by hand

The kept branch waits for a human to read run.md and merge.

There is no polling and no lock. A card is held only while the process that took it is alive.

The record

The card folder is the whole record. There is no database and no second store; run.md is a rendering of the folder, and every outcome also lands in a hash-chained log you can verify.

.thompson/board/done/<card-id>/
  card.md              the task, acceptance and check
  baseline.md          the score on the base, taken by hand first
  attempts/r1/c1/      prompt, reply, diff, critique
  attempts/r1/c2/      the corrected attempt
  attempts/r2/…        the second rollout
  verdict.json         what the judge ran and what it said
  run.md               the readable story of the card

Yesterday's first real card removed the lease from the port: both attempts were judged, the change was merged on John's word, and 216 tests stayed green.

Install: paste this into your agent

Open Claude Code, or another coding agent, in the repository you want Thompson to work on, and paste this. The agent installs the thompson command if it is missing, starts a board, turns on the plugin for that project, and ends by telling you to type /thompson.

Install Thompson in this repository and turn on its Claude Code plugin. Run each step yourself, and if one fails, stop and tell me what failed.

1. Check that `git` and `bun` are installed (`git --version`, `bun --version`). If bun is missing, tell me to install it from https://bun.sh and stop.
2. If `command -v thompson` finds nothing, install the Thompson command:
   git clone -b claude/lightweight-harness-18lhg4 https://github.com/wisbech/thompson ~/thompson
   cd ~/thompson && bun install && bun link
   Then use `export PATH="$HOME/.bun/bin:$PATH"` for the rest of these steps, and tell me to add that line to my shell profile if `~/.bun/bin` is not already on my PATH.
3. Back in this repository's root (it needs at least one commit), run `thompson init` unless a `.thompson/` folder already exists.
4. Turn on the plugin for this project:
   claude plugin marketplace add wisbech/thompson#claude/lightweight-harness-18lhg4
   claude plugin install thompson@thompson --scope project
   If the install says a userConfig option is not set, leave it: it defaults to the `thompson` command.
5. Show me the `.claude/settings.json` the install wrote and offer to commit it. Do not commit anything else.
6. Tell me to run /reload-plugins (or restart Claude Code), then add a first card with `thompson task "<title>" --accept "<what done means>" --verify "<a command that exits 0 when done>"` and type /thompson.

(Until Thompson's PR #1 is merged to main, the commands name the branch claude/lightweight-harness-18lhg4; once it is, drop `-b claude/lightweight-harness-18lhg4` and `#claude/lightweight-harness-18lhg4`.)

Try it by hand

In a git repository with at least one commit on main:

bun install
thompson init
thompson task "say hello" --accept "hello.txt exists" --verify "test -f hello.txt"
thompson next --json                # prints workDir: edit there
echo hi > <workDir>/hello.txt
thompson submit <id> --json         # judged: passed goes to done, failed to review
thompson log verify

To let models do the work, point the refine host at a card:

bun adapters/refine/refine.ts --n 2 --d 2 --record docs/runs --json

Problems to grow

Agent problems after the Generative Design 02_M sketches: noise-driven agents (M_1_5), repelling nodes and springs (M_6_1, M_6_2) and recursion (M_5_1). In each one the judge owns the world (the field, the physics, the food, the graph) and the worker writes only the agent: how it senses, steers and leaves a mark. Worlds are seeded from the commit being judged, and every run has a fixed time budget, so a better score means a better rule.

M_1_5 · noise agents

Flow Start here

Agents ride the judge's noise field and must cover the page with evenly spaced trails. The look of the M_1_5 prints, made into a target.

writes
where each agent starts and when it stops
check
trails follow the field within 5°, never closer than the spacing, 10 s
score
share of the page within one spacing of a trail, over three fields
Physarum · agents

Slime

Thousands of sensing, depositing agents grow a network between food sources, the way slime mould rebuilt the Tokyo rail map.

writes
sensor angle and distance, turn rule, deposit
check
the judge's trail map connects every food source
score
spanning-tree length over network length; a Steiner tree reaches about 1.15
M_6_1 · springs

Web

Nodes repel and edges pull until a slice of the Wikipedia link graph untangles, as in M_6_1_03 and M_6_2.

writes
the force rules and the cooling schedule
check
inside the frame, no overlapping nodes, within budget
score
fewer edge crossings, with a small term for even edge lengths
boids · agents

Flock

Two hundred agents cross an obstacle field. Flocking emerges from local rules; here the rules evolve under a goal.

writes
a steering function that sees only its neighbourhood
check
the judge owns speed, turning and collisions
score
share arriving, minus a penalty per collision
M_5_1 · recursion

Canopy

Grow the recursive branching of M_5_1_01 into a tree that catches the most light for the least wood.

check
one connected tree, no crossings, pipe-model thickness
score
sun rays caught per unit of wood

Kept from the first draft as options: Pack (circles in a silhouette), Coral (diffusion-limited aggregation) and Methuselah (the longest-lived Game of Life seed). The full proposal, with what an improving run looks like for each, is visual-problems/visual-problems.md in the project files.
